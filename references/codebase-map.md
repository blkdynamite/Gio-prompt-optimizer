# Codebase Map

A labeled, regenerable index of the repository — module → file → one-line
purpose → key symbols with line ranges — so an agent jumps straight to the right
place instead of re-discovering the structure every task. Think of it as the
library catalog: you read the catalog to find the shelf, then pull the book to
read the page.

Generated by `scripts/codebase_map.py`. Outputs two files at the repo root:

- **`CODEBASE_MAP.md`** — human/agent skim-readable, grouped by directory.
- **`.codebase-map.json`** — machine-parsable; carries `line_start`/`line_end`
  per symbol plus per-file `mtime` + `sha` for staleness detection.

Both are regenerable and gitignored by default. Commit `CODEBASE_MAP.md` if you
want teammates to get it without regenerating.

## The map-then-verify protocol (important)

A static index drifts the moment code changes, and an agent that trusts a stale
map will be confidently wrong. So the map is a **pointer, never the source of
truth**:

1. **Map** — find the file and line range for what you need. For a single symbol,
   prefer `--find SYMBOL` (returns just the `file:line` slice, no whole-map load —
   the cheapest path); skim `CODEBASE_MAP.md` when you need the broader layout.
2. **Verify** — `Read` exactly that span (`offset`/`limit`) to confirm the code
   still matches the map before you reason about or change it.
3. **Heal** — if the span doesn't match (symbol moved/renamed/gone), fall back to
   `Grep` for the symbol, and regenerate the map (`python3
   scripts/codebase_map.py`) so the next lookup is correct.

> **Token note:** on a *small* repo, reading the whole `CODEBASE_MAP.md` can cost
> more than just grepping — measured at ~11% worse than plain search. `--find`
> avoids that by returning only the matching locations, and the map's advantage
> grows with codebase size. Reach for `--find` first; skim the full map only when
> you genuinely need the layout.

This keeps the token win of "don't re-scan the repo" while staying safe against
staleness, because you always read ground truth before acting.

## When to use it

- **Read the map first** on any task in an unfamiliar or large repo — it replaces
  the "spawn an Explore agent / grep around to understand the layout" step.
- **Generate/refresh it** at the start of a session, and after any change that
  moves code (new files, renames, large refactors).
- **Skip it** for a one-file change you already have in context, or a repo small
  enough to hold in your head.

## Generating and checking

```bash
python3 scripts/codebase_map.py                 # write CODEBASE_MAP.md + .codebase-map.json
python3 scripts/codebase_map.py --find cost_usd # just the file:line of a symbol (cheapest lookup)
python3 scripts/codebase_map.py --root .        # map a specific directory
python3 scripts/codebase_map.py --check         # report drift vs the stored map; exit 1 if stale
python3 scripts/codebase_map.py --stdout        # print the Markdown map without writing files
python3 scripts/codebase_map.py --json          # machine-readable map to stdout
python3 scripts/codebase_map.py --engine ast    # force an engine
python3 scripts/codebase_map.py --help
```

`--find` matches functions, classes, methods (by basename), and module-level
constants — exact matches first, then case-insensitive substring. It reads the
stored `.codebase-map.json` (building one in memory if absent), so the result is
a few lines an agent can act on immediately.

`--check` exits non-zero on drift, so it doubles as a pre-commit / CI guard:
*"is the committed map still accurate?"*

## How symbols are extracted (tiered, zero hard deps)

The generator is stdlib-only, but **uses high-performance tools automatically
when they're installed** — and degrades gracefully when they aren't:

| Tier | Engine | Covers | Notes |
|---|---|---|---|
| 1 | **tree-sitter** (`tree_sitter_language_pack`) | 40+ languages | Best precision. Optional — used only if importable. |
| 2 | **universal-ctags** (`ctags` on PATH) | 100+ languages | Broad. Optional — used only if installed. |
| 3 | **stdlib `ast`** | Python | Always available; exact line ranges + docstring purpose. |
| 4 | **regex heuristic** | any language | Last resort for files no better engine handled. |

Markdown files are always mapped by their headings (handy for docs navigation).
`--engine auto` (default) picks the best available; force a specific tier with
`--engine treesitter|ctags|ast|regex`. To get the top tier:

```bash
pip install tree-sitter-language-pack    # optional; enables the tree-sitter tier
```

File discovery honors `.gitignore` (via `git ls-files`, including not-yet-tracked
files) and skips vendored/generated dirs and files larger than `MAX_FILE_BYTES`.

## Tuning

All knobs are constants at the top of `scripts/codebase_map.py`, each documented
inline: `DEFAULT_IGNORES` (dirs to skip), `MAX_FILE_BYTES`, `LANG_BY_EXT`
(extensions → language), `DEFAULT_MAX_SYMBOLS_PER_FILE` (Markdown view cap — the
JSON always keeps everything), and the regex/tree-sitter definition patterns.

## Why this saves tokens

Locating code by re-reading files or fanning out search agents every task is the
single most expensive habit (Part 1). The map pays that discovery cost **once**,
then every later task spends a tiny map lookup plus one targeted span read,
instead of re-deriving the layout from scratch. Map-then-verify keeps that
cheaper path honest.
